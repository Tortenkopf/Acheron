Acheron — architectural friction

The first pass (2026-09-03) surfaced seven candidates. Candidate 1 — the config::binding::check_binding seam — shipped as post-release ticket 14. The other six were re-verified against current code for this pass; the line and site counts below are corrected where the first pass was loose.

One force reshapes the priority order: the tartarus-dual-stage-keys effort, now charting, will add a third Depth-fed engine (stage::Engine, sibling to axis / analog_repeat) with its own StageKey-keyed firing/toggle maps, its own slot_for, and its own teardown fan-out. Two of the carried-forward candidates stop being insurance and become load-bearing before the dual-stage spec is even written.

dispatch.rs is 4473 lines but implementation ends at line 1127; config.rs is 2935 lines, implementation ends at 1364. Neither is a monolith — the friction is in duplicated runtime protocol, a mechanism trapped inside the wrong module, and seams that were half-carved and stopped.

1  A trigger::Slots<K> module for the firing/toggle handle pair

Strong in-process carried forward · #3

daemon/src/dispatch.rs trigger_ctx! (64–76), ChordRuntime (85–88), DispatchState.{toggles, in_flight} (100–101), chord_slots (870–884), slot_for (895–908), TriggerCtx + perform_trigger (918–974) · daemon/src/chord.rs feed(…, live: &HashMap, …) (117–121) · daemon/src/trigger.rs Slot, TriggerDecision (42–60) · .scratch/tartarus-dual-stage-keys/issues/01 §2, §4

Before — the same pair open-coded 2½ times

After — one deep struct, three fields

Problem. The (HashMap<K, FiringHandle>, HashMap<K, ActiveToggle>) pair and the three operations always done on it — read one key's liveness (slot_for), snapshot all of it (chord_slots), perform a decision (perform_trigger) — is a module that does not exist. It is open-coded twice today; slot_for and chord_slots carry deliberately inverse tie-breaks (firing-wins vs toggle-wins) whose only guard is a doc comment on dispatch.rs:892. The dual-stage spec adds a third copy.

Solution. A trigger::Slots<K> owning both maps, with slot / snapshot / perform as methods. Two interface options for the grilling step: (a) the conservative struct — dispatch, chord and stage each hold one as a field; (b) the first-pass proposal — push it inside chord/trigger so feed loses its live parameter entirely.

  • locality: one precedence rule, next to its state
  • the slot_for/chord_slots divergence becomes one deliberate method (or two clearly-named ones)
  • leverage: stage::Engine becomes Slots<StageKey> for free
  • tie-break tested as a table in trigger.rs, not through a dispatch integration path
  • deletes the trigger_ctx! macro (a documented &mut self workaround)
  • deletion test: delete Slots and the two-map bookkeeping + tie-break scatter back across three structs

Re-verification note. The first pass argued a third connection-scoped subscription would make this three copies. The dual-stage effort (map.md Q14, ticket 01) confirms no new signal and no new GetState() field — so this stays a two-copy duplication. Still Strong: six in-place copies of a subtle abort-and-supersede race is enough on its own.

Problem. SuppressionState and DepthStreamState are two hand-rolled copies of the same connection-scoped-resource-with-disconnect-cleanup protocol; the "bump epoch + abort in one locked section, then store/clear only if still current" rule is written out in six places.

Solution. A ConnectionScopedTask<S> module owning epoch + watcher + the arm / supersede / disconnect-clear protocol.

  • locality: one subtle race, one module
  • the race is tested directly with fake tasks, not through a live zbus server
  • interface shrinks; the implementation absorbs the epoch discipline
  • six epoch-guard copies collapse to one
  • deletion test: complexity concentrates, not spreads

ADR-0006 check. ADR-0006 fixes who drives the Status LEDs (dispatch) and the fd lifetime (short-lived Interface-2 hidraw) — not where the frame builder lives. Moving the Razer-frame primitives into a shared device_control module is consistent with it, not a reopening. Confirm with the domain owner before acting.

Problem. Status-LED writing, firmware/serial reading, analog unlock/relock and kernel-autorepeat reading share only a mechanism — a short-lived Interface-2 hidraw fd plus a Razer command frame — yet that mechanism lives as private helpers inside the Analog Capture mode module. dispatch imports DeviceInfo and executor imports read_kernel_auto_repeat from capture::analog purely by accident of location.

Solution. Extract the fd + frame + CRC + exchange primitives into a device_control module; move DeviceInfo into a device_info module beside it; led, device_info and capture::analog become thin callers.

  • the seam moves to where behaviour actually varies
  • the frame/CRC logic gets its own name and its own tests
  • DeviceInfo stops living under capture
  • deletion test: the primitives are used four ways — they would reappear

4  One plug-in contract for the Depth-fed engines

Worth exploring in-process carried forward · #6, widened

daemon/src/dispatch.rs AxisWrite drain loop verbatim at 228–229, 403–404, 555–556, 577–578, 1018–1019 · engine teardown fan-out: handle_layer_switch (1001), handle_capture_mode_change (1057), run_effects stop-all (574–580), disconnect · daemon/src/axis.rs AxisWrite (56) · daemon/src/analog_repeat.rs stop_all · .scratch/tartarus-dual-stage-keys/issues/01 §5

Before — two duplications, one per engine, growing

a — AxisWrite drain, 5 verbatim copies

for w in axis.<m>(…) { injector.set_axis_value(w.code, w.value).await }

handle_event · handle_depth_update · handle_layer_switch · RecomputeAxes · ResetAxisOutputs

b — teardown fan-out, once per engine

axis.reset()
analog_repeat.stop_all()
stage.stop_all() (coming)

… each hand-wired into the same 4 lifecycle points: layer switch, capture-mode flip, profile switch, disconnect.

After — one emit path, one teardown call

injector.set_axis_values(&[AxisWrite]) — batch, one home
all 5 sites → self.emit_axis(writes).await
self.depth_engines_reset().await — fans to axis + analog_repeat + stage

The next Depth-fed engine plugs into one contract instead of four call sites.

Problem. Every axis::Engine method returns Vec<AxisWrite> and dispatch runs the identical drain-to-injector loop at five sites; separately, each Depth-fed engine's teardown (reset / stop_all) is hand-wired into the same four dispatch lifecycle points. There is no single "a Depth engine plugs in here" contract — and stage::Engine is about to need one.

Solution. Push AxisWrite into injector with set_axis_values(&[AxisWrite]) and give DispatchState one emit_axis method; then a single teardown fan-out method (or a small DepthEngine trait) the lifecycle points call once.

  • locality: the next axis-output or teardown change is one edit
  • leverage: stage::Engine registers once instead of at four call sites
  • one focused test instead of five integration paths
  • widened from the first pass's Speculative — the third engine makes it real

5  Finish the config/ carve that ticket 14 started

Worth exploring in-process new

daemon/src/config.rs (1364 impl lines, flat) — serde vocab (45–780), ChordKey 5 trait impls (288–357), MacroId/StepperId newtypes (656–735), ConfigError (840–942, 40 variants) + Display (944–1043), load_or_seed (1049), parse (1095), find_legacy_macro_bindings (1068), validate (1137), write (1329–1344) · daemon/src/config/binding.rs (already carved, ticket 14) · daemon/src/edit.rs From<ConfigError> for CommandError (793)

Before — three concerns nose-to-tail, one seam carved

After — the dir gets the rest of its modules

Honest weight. config/error.rs is a pure relocation — data plus a Display impl, so its deletion test is weak (it concentrates knowledge, not behaviour). The config/io.rs cut — parse, the raw toml::Value legacy-migration walk, write — is the one with real behaviour behind a small interface.

Problem. Ticket 14 created config/ but moved only the per-binding rules into it. The parent file still holds the serde vocabulary, a self-contained 40-variant error catalog, and the load/parse/migrate/write pipeline nose-to-tail with no internal seam — and ConfigError is already consumed from config/binding.rs and edit.rs, across a boundary that does not formally exist.

Solution. Continue the carve: config/error.rs (the catalog + Display + the From conversions) and config/io.rs (load / parse / migration / write / slug).

  • locality: "everything that can go wrong loading a config, and the words the user sees" is one file
  • the 1570-line mod tests splits along the same lines
  • leverage: schema.rs and binding.rs already import pieces — the module makes it deliberate
  • no ADR exposure; config/ is already an established dir

6  A contract test for the D-Bus a{sv} wire shape

Worth exploring mock carried forward · #5

daemon/src/dbus/wire.rs action_to_dict/_from_dict (242/277), profile_to_dict (391, encode-only), config_to_dict (523), state_to_dict (550), "omit empty modifiers" test (638, daemon-side only) · gui/acheron_gui/wire.py *_to_variant (encode-only) · gui/tests/test_wire.py self round-trip only · daemon/src/schema.rs render_schema (263) — no encoded example dicts

Before — the contract stops short of the wire

After — the deliberate copy is contract-tested end to end

ADR-0003. The model is copied across the process seam on purpose — that is not the friction. The friction is a partial contract test that stops short of the wire shape, giving false confidence. This adds a contract test of the deliberate copy; it does not challenge the copy.

Problem. The rules.py contract covers the verdict matrix and the catalogs but not the a{sv} encoding — tag strings, field names, the "omit empty modifiers" rule — and no test runs wire.py output against wire.rs input.

Solution. Have schema.rs emit fully-encoded example dicts per variant; a new test_wire_contract.py asserts wire.py matches them byte-for-byte and wire.rs::*_from_dict round-trips them.

  • closes the one cross-stack gap the language split leaves
  • a renamed tag fails a test, not a review
  • test_wire.py's self round-trip becomes a real contract

7  A typed read accessor over the GetConfig dict

Speculative in-process carried forward · #7

gui/acheron_gui/read_model.py ("deliberately not a read-model, ADR 0005") · raw digs: device_overview.py (363, 364, 558, 770, 829, 838, 848) · binding_editor.py (279, 684, 881, 887) · library_view.py (509) · daemon_stub.py (223, 260, 313, 331, 351, 354, 358) · gui/acheron_gui/app.py rebuild (~511), ui_state (~508)

Before — every view digs the raw dict

After — one accessor absorbs the traversal

ADR-0005 flag. read_model.py's docstring cites ADR-0005 to resist exactly this. ADR-0005 protects the GUI's hand-mirror of the daemon's stateful edit validation (daemon_stub.py). A read-only accessor over GetConfig's own output is a different thing — but close enough to the ADR's spirit that it needs the domain owner's ruling before acting. This is why it drops to Speculative for this pass.

Problem. The config payload is an untyped dict whose schema is implicit; every view re-implements traversal with string-built keys (f"axis_{layer}"), and rebuild is threaded as the universal change signal through nearly every builder alongside an ad-hoc ui_state bag.

Solution. A thin typed ConfigView read accessor over the wire payload — not the stateful edit mirror ADR-0005 protects — generalising the one scan read_model.py already does.

  • locality: the dict schema is known in one place
  • the f"axis_{layer}" typo surface collapses
  • views become testable against a fixture, not a full raw dict

Investigated, not a candidate

edit::Effect as a two-enum shuffle

Edit → plan → Outcome{effects} → run_effects is one intermediate enum at a deliberate pure/impure seam. Each run_effects arm is short because plan already decided. This is the target shape.

dispatch::run's wide signature

Ticket 09 already carved DispatchState and added the Seam test helper. The wide run signature is pure channel wiring with a rationale comment. Addressed.

daemon_stub.py drift

_validate_binding_action already delegates the pure half to rules.py; only the ~150-line stateful half is hand-mirrored, which ADR-0005 explicitly chooses. Off-limits.

injector.rs / capture/supervisor.rs

Both genuinely deep: message-passing actor behind a handle, a real two-adapter seam (InjectSink, CaptureSource), swap protocols hidden inside. Examples of the target, not targets. injector only gains #4's batch method.

No daemon/tests/ directory

Every daemon module tests through an in-process seam (channels, InjectSink, Seam, a real zbus TestServer). Large test-line counts, but the seams exist and are exercised. Not a testability failure.

Top recommendation

Start with #1 — trigger::Slots<K>

It is the one piece of friction the tartarus-dual-stage-keys effort actively worsens before its spec is written: a third firings/toggles keyspace, a third slot_for, a third trigger_ctx!. The inverse tie-break between slot_for and chord_slots is a real bug surface guarded only by a comment. The conservative Slots<K> cut has a blast radius entirely inside dispatch.rs and trigger.rs, no ADR exposure, and immediate test leverage — and it hands the dual-stage implementation a ready seam instead of a fourth copy to write.

Runner-up: #2 — ConnectionScopedTask. Also Strong; the abort-and-supersede race is copied across six sites today. Independent of the dual-stage schedule, so it can land any time.

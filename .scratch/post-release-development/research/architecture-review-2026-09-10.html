1 · Concentrate the runtime-orphan cascade in edit

Strong in-process
daemon/src/edit.rs · plan() arms + cascade_replaced_toggle / cascade_orphaned_deep_stage
daemon/src/dispatch.rs · run_effects (StopToggle / StopStage / StopChord)

Before — every arm re-derives its own teardown

After — arms mutate; one module diffs before/after

Problem
Eight plan arms each hand-derive which live runtime slot they just orphaned and push its teardown Effect — a shallow rule smeared across the match.
Solution
Arms mutate the Config clone only. One pure reconcile(before, after) module diffs the two and emits every Stop* effect.
Deletion test
Delete the cascade helpers → the orphan rules reappear in 8 callers. Concentrates: a real seam.
Fits the existing contract
plan is already pure and blind to liveness; it already emits Stop* unconditionally and run_effects already no-ops when nothing is live.
  • locality: one place owns "edit X orphans slot Y"
  • leverage: one diff path, every Edit variant
  • interface shrinks; arms lose their tendrils
  • a new engine adds one diff clause, not N arm edits
  • tests: (before, after) → effects truth table
  • closes the ticket 18→24 omission class structurally
Cuts against ticket 20's per-arm disposition and CONTRIBUTING's "add an Effect only if there's a side effect" pattern — no ADR forbids it (ticket 20 wrote none). Worth reopening: tickets 18, 21, 22, 23, 24 are five consecutive patches to the same missing-teardown class, and ticket 24's fix landed this week. Adjacent to ADR-0010 (the lifecycle matrix) but a different axis — tear_down handles Layer/Profile/disconnect sweeps; this handles config-edit orphans.

2 · Extract a pure BindingDraft from the binding editor

Worth exploring local-substitutable
gui/acheron_gui/binding_editor.py · build_dual_stage_panel (~640 L), build_action_and_trigger_fields (~500 L), build_binding_editor
gui/tests/test_binding_editor.py · 2212 L — the largest file in the repo

Before — interface ≈ implementation (shallow)

After — thin interface, deep model + adapter

Problem
Draft validity and primary/deep composition live as ~50 closures over GTK widget state; the interface is as wide as the implementation.
Solution
A plain BindingDraft value owns the draft, its validity, and the edits to push on Save. The panel renders it and forwards input.
Not a rules.py duplicate
rules.py mirrors daemon legality; BindingDraft owns editor composition and calls into rules.
Signal
Recent bugs — dual-stage seed, unbound-key picker default, reset-to-default deep band — all hid in closure coordination, not GTK.
  • interface is the test surface: construct a draft, assert
  • locality: composition bugs concentrate in one value
  • the 2212-line test file sheds its widget scaffolding
  • leverage: the same draft feeds grid, non-grid, and Chord panels
Consistent with ADR-0003 (split-language stack): the GUI keeps its own copied, contract-tested model. This deepens that model rather than reaching across the D-Bus seam.

3 · A dispatch::ActiveView computed once per tick

Speculative in-process
daemon/src/dispatch.rs · handle_event · handle_depth_update · update_analog_repeats · update_stages · tick_stages · dispatch_individual_down

Before — each handler re-resolves the active view

flowchart TD
  D["rx_depth arm — one snapshot"] --> H1["handle_depth_update"]
  D --> H2["update_analog_repeats"]
  D --> H3["update_stages"]
  H1 --> R1["active_profile().expect()
+ .axis_layer(active_layer)"]
  H2 --> R2["active_profile().expect()
+ .layer(active_layer)"]
  H3 --> R3["active_profile().expect()
+ EngineDeps{7 fields}"]
  classDef dup stroke:#dc2626,stroke-width:2px,fill:#fee2e2;
  class R1,R2,R3 dup

~7 active_profile().expect() sites · EngineDeps literal built identically 3×

After — resolve once, pass the view

flowchart TD
  D["rx_depth arm — one snapshot"] --> V["ActiveView::resolve(&config, active_layer)"]
  V --> H1["handle_depth_update(view)"]
  V --> H2["update_analog_repeats(view)"]
  V --> H3["update_stages(view)"]
  classDef deep fill:#0f172a,color:#e2e8f0,stroke:#0f172a;
  class V deep

one resolve point · bindings, chords, axis_map, resolved actuation held together

Problem
"The active Profile's active-Layer resolved view" is re-derived ~10× across dispatch handlers, each with the same .expect() preamble.
Solution
One ActiveView value resolved per rx_events / rx_depth tick, handed to the handlers.
  • locality: layer/profile resolution in one place
  • interface: handlers take one param, not &config + active_layer
  • the repeated EngineDeps literal collapses
Not a DepthEngine trait — ADR-0010 rejected unifying the engines, and ticket 10 declined a depth:: umbrella. This is a read-model over Config, not engine unification — but the area has twice resisted consolidation, so weight the win modestly. Value is small: each duplicated site is short and type-checked today.

Top recommendation

1 · Runtime-orphan reconciliation in edit

It is the codebase's live wound: tickets 18, 21, 22, 23, and 24 are five consecutive fixes for one arm or another of plan forgetting its teardown Effect, and 24 landed days ago. The lifecycle matrix already got this treatment (tear_down + ADR-0010); the config-edit axis is still open-coded per arm. A pure reconcile(before, after) concentrates the rule, gives it a truth-table test, and makes the whole omission class structurally impossible — the strongest locality win on the board.

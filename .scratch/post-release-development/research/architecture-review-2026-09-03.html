Acheron — architectural friction

2026-09-03 · dev branch · daemon 1.1.0

solid box = module

The post-release effort (tickets 05–13) already carved chord, trigger, stepper, axis, analog_repeat and the config-transaction logic out of dispatch.rs. dispatch.rs is 4473 lines but only lines 1–1127 are implementation — it is not a monolith. The friction that remains is in the glue between dispatch and the pure modules, in duplicated concurrency protocol on the D-Bus surface, and in a monolithic validation walk that three other artifacts reconstruct by brute force.

1  Split config::validate at the per-binding seam

Strong in-process

daemon/src/config.rs validate (1126–1348) · daemon/src/schema.rs trigger_verdict, action_kind_verdict (184–230) · gui/acheron_gui/rules.py valid_action_kinds, valid_triggers · daemon/contract/daemon-schema.json

Before — one 220-line walk

validate
&Config → Result
profile-switch trigger walk
controller-button code walk
controller-button trigger walk
dangling macro_id walk
dangling stepper_id walk
step-trigger walk
analog-repeat input walk
… ~13 more, order load-bearing

schema.rs synthesizes a 2-profile Config, inserts one binding, runs the whole wall, keeps one bit — per matrix cell. rules.py hand-transcribes the same matrix as set algebra.

After — pure check + config pass

check_binding
Option<Input>, &Binding
every per-binding legality rule
exhaustively table-tested, ~40 lines
validate
for b in all_bindings: check_binding(b)?
whole-Config pass (dangling refs, hysteresis)

schema.rs calls check_binding per cell — no synthetic Config. rules.py mirrors one named function, not a matrix reverse-engineered from a monolith.

Problem. validate conflates pure per-binding legality with whole-Config reference checks, so the per-binding rule is an emergent property that schema.rs and rules.py each reconstruct by brute force.

Solution. Extract a pure check_binding(Option<Input>, &Binding) → Result; validate loops it and then runs the whole-Config checks as a separate pass.

  • locality: one binding rule, one place
  • leverage: daemon, schema, and GUI mirror share it
  • tests read as a truth table
  • contract fixture stops synthesizing Configs
  • deletion test: interface enforcement stays, monolith dissolves

3  Push the firing/toggle handles into the pure machines

Worth exploring in-process

daemon/src/dispatch.rs DispatchState + ChordRuntime (84–156), chord_slots (870–884), slot_for (895–908), trigger_ctx! macro (54–76), perform_trigger (935–974) · daemon/src/chord.rs feed/tick take live: &HashMap · daemon/src/trigger.rs decide takes slot: Option<Slot>

Before — machine here, handles there

After — one ring further out

Problem. The pure modules own their logic state but not the firing/toggle handles, so every call into them makes dispatch rebuild a liveness snapshot — via two readers (chord_slots, slot_for) with deliberately inverse tie-breaks, a real bug surface guarded only by a comment.

Solution. Move the ChordKey-keyed handle maps into chord/trigger as private fields (or behind a one-impl Liveness trait), so feed loses its live parameter and the precedence rule has one home.

  • locality: one precedence rule, next to its state
  • the slot_for/chord_slots divergence becomes impossible
  • chord tests drive real liveness, not a reconstruction
  • interface shrinks: feed drops an argument
  • deletes the trigger_ctx! macro

ADR-0006 check. ADR-0006 fixes who drives the Status LEDs (dispatch) and the fd lifetime (short-lived) — not where the frame builder lives. Moving the Razer-frame primitives into a shared device_control module is consistent with it, not a reopening. Confirm with the domain owner before acting.

Problem. Status-LED writing, firmware/serial reading, and analog unlock share only a mechanism — a short-lived Interface-2 hidraw fd plus a Razer command frame — yet that mechanism lives as private helpers inside the Analog Capture mode module, and dispatch imports DeviceInfo from capture purely by accident of location.

Solution. Extract the fd + frame + CRC + exchange primitives into a device_control module; led, device_info and capture::analog become thin callers of it.

  • seam moves to where behaviour actually varies
  • the frame/CRC logic gets its own name and tests
  • DeviceInfo stops living under capture
  • deletion test: the primitives are used 4 ways — they'd reappear

5  A contract test for the D-Bus a{sv} wire shape

Worth exploring mock

daemon/src/dbus/wire.rs action_to_dict/_from_dict (242–310), binding_to_dict, the "omit empty modifiers" rule · gui/acheron_gui/wire.py action_to_variant (encode only) · gui/tests/test_wire.py round-trips wire.py against itself

Before — the copy has a gap in its contract

After — the deliberate copy is contract-tested end to end

ADR-0003. The model is copied across the process seam on purpose — not the friction. The friction is a partial contract test that stops short of the wire shape, giving false confidence. This adds a contract test of the deliberate copy; it does not challenge the copy.

Problem. The rules.py contract covers the verdict matrix and catalogs but not the a{sv} encoding — tag strings, field names, the "omit empty modifiers" rule — and no test executes wire.py output against wire.rs input.

Solution. Have schema.rs emit fully-encoded example dicts per variant; a new test_wire_contract.py asserts wire.py matches them byte-for-byte and wire.rs::*_from_dict round-trips them.

  • closes the one cross-stack gap the split leaves
  • a renamed tag fails a test, not review
  • test_wire.py's self round-trip becomes real

6  Give the AxisWrite emit loop one home

Speculative in-process

daemon/src/dispatch.rs handle_event (226–233), handle_depth_update (403–405), handle_layer_switch (1018–1020), run_effects RecomputeAxes (555–557) + ResetAxisOutputs (577–579) · daemon/src/axis.rs AxisWrite (55–59)

Before — the same 3 lines, 6 places

handle_event → for w in writes { injector.set_axis_value(w).await }
handle_depth_update → for w in writes { … }
handle_layer_switch → for w in writes { … }
RecomputeAxes → for w in writes { … }
ResetAxisOutputs → for w in writes { … }

A sync frame / batching / suppression change = a 6-site edit.

After — one emit method

handle_event → self.emit_axis(writes).await
handle_depth_update → self.emit_axis(writes).await
… all 5 sites, one line each
emit_axis(&self, Vec<AxisWrite>) — or injector.set_axis_values(&[..])

axis.rs can own AxisWrite end to end.

Problem. Every axis::Engine method returns Vec<AxisWrite> and dispatch does the identical drain-to-injector loop at ~6 sites; the AxisWrite → injector step has no single home.

Solution. One emit_axis_writes method on DispatchState, or push AxisWrite into injector with a set_axis_values(&[AxisWrite]).

  • locality: the next axis-output change is one edit
  • one focused test instead of 6 integration paths
  • small — real only as insurance

7  A typed read-model over the GetConfig dict

Worth exploring in-process

gui/acheron_gui/app.py rebuild (511–554), ui_state (502) · gui/acheron_gui/read_model.py (38 lines, "deliberately not a read-model") · raw digs in device_overview.py, binding_editor.py, library_view.py (~17 sites)

Before — every view digs the raw dict

After — one accessor absorbs the traversal

ADR-0005 flag. read_model.py's docstring cites ADR-0005 to resist exactly this. ADR-0005 protects the GUI's hand-mirror of the daemon's stateful edit validation (daemon_stub.py). A read-only accessor over GetConfig's own output is a different thing — but close enough to the ADR's spirit that it needs the domain owner's ruling before acting.

Problem. The config payload is an untyped dict whose schema is implicit; every view re-implements traversal (f"axis_{layer}" string-built keys), and rebuild is threaded as the universal change signal through nearly every builder with an ad-hoc ui_state bag.

Solution. A thin typed ConfigView read accessor over the wire payload — not the stateful edit mirror ADR-0005 protects — generalising the one scan read_model.py already does.

  • locality: dict schema known in one place
  • the f"axis_{layer}" typo surface collapses
  • views testable against a fixture, not a full raw dict

Top recommendation

Start with #1 — split config::validate

It is the one Strong candidate whose payoff compounds: a pure check_binding seam is the missing counterpart to the GUI's rules.py, it lets schema.rs stop synthesizing throwaway Configs, it makes per-binding legality testable as a truth table, and — per the subagent's note — it may later let daemon_stub.py delegate more of its hand-written surface to a contract-tested mirror, without touching what ADR-0005 protects. No ADR conflict, contained blast radius, immediate test leverage.

Runner-up: #2 — ConnectionScopedTask. Also Strong; the disconnect race is duplicated today and a third connection-scoped subscription makes it three.

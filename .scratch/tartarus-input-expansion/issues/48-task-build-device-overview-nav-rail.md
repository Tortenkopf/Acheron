## Answer

Landed exactly to ticket 47's round-2 (variant D) design in `device_overview.py`. `build_profile_sidebar` is otherwise untouched but now ends with an explicit `sidebar.set_hexpand(False)` — the round-2 fix for GTK4's expand-propagation widening it under the Library destination. `build_main_view`'s old profile-sidebar+grid+`table_revealer`/`table_toggle`+tray-mock assembly is replaced with: the same pinned sidebar; a new `build_destination_switch` (plain-text "Grid"/"Library" buttons, `ui_state["dest"]` persisted the same way `selected_layer` already was) where the old Action-Table toggle sat; a `Gtk.Separator`; then per-destination content that fully replaces the content area. The Grid destination keeps the real `build_layer_bar` above the grid+thumbstick assembly (unchanged) with a `device_row.set_margin_top(8)` between them per round 2's crowding fix, plus a new always-visible `build_chords_placeholder()` slot beside the grid naming ticket 40. The Library destination is a new `build_library_placeholder()` naming ticket 41. The tray mock's sensible home is unchanged — still the last thing appended to `root`, alongside the sidebar and the new switcher column, so it's visible regardless of which destination is selected.

Action Table cut outright: `action_table.py` and `test_action_table.py` deleted (`build_action_table`/`build_table_row` had no remaining caller), and `ui_state["table_open"]`/`ui_state["expanded_rows"]` removed from both `device_overview.py` and `app.py`'s own `ui_state` initialization (replaced with `ui_state["dest"]`). `binding_editor.py`'s module docstring updated — it no longer describes itself as shared with "the Action Table sidebar's expandable rows."

`test_device_overview.py` updated for the new structure: the two Action-Table-specific tests are gone, `_action_table_toggle` replaced with a `_dest_switch_button` helper, and new tests cover the Grid/Library switch itself (default destination, persistence across a rebuild via `ui_state["dest"]`, Library fully replacing the content area with no grid/layer-bar/Chords in sight), the Chords/Library placeholders naming tickets 40/41, and — the ticket's own regression concern — that `build_profile_sidebar`'s `get_hexpand()` is `False` in both destinations. Every pre-existing Profile CRUD/Base-Held/mode-key-role/status-overlay test needed no logic changes beyond dropping the now-unnecessary `{"table_open": False}` seed, confirming those flows still work unchanged through the new Grid destination. 121 Python tests green (was 121 before this ticket too — net zero after subtracting the retired Action Table tests and adding the new destination-switch coverage). No Rust changes.

`/code-review` flagged two real findings in this diff: `build_destination_switch` structurally duplicates `build_layer_bar`'s selectable-tab-row shape (judged acceptable — the two functions differ in what else they render per tab, and the repo's own "three similar lines beats a premature abstraction" standard applies), and `build_main_view`'s Library branch duplicated its own two-line `root.append(right); root.append(build_tray_mock(...)); return root` tail — fixed by restructuring to a single `if/else` that falls through to one shared exit. (The review's other findings were all in already-committed code from earlier tickets — `controller_picker.py`, `daemon/src/main.rs`, `daemon/src/config.rs` — untouched by and out of scope for this ticket.)

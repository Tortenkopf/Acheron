**Live-tested follow-up correction**: the user ran the built GUI and reported the Macro/Stepper browse list (column 1) reading noticeably shorter than the column's own available height — a slab of dead space beneath it. Root cause: `build_macros_browse_list`/`build_steppers_browse_list`'s `rows_scroller` still carried ticket 61's original `propagate_natural_height(True)` + `max_content_height(240)` treatment, sized for the old two-column layout where the browse list shared a row with a same-height editor. Column 1 now spans the full Grid/chords height with nothing else below the list, so that 240px cap left it visibly stubby. Fixed by dropping both calls in favor of `rows_scroller.set_vexpand(True)` — the ScrolledWindow now claims whatever height column 1 actually has (matching the window, whatever size that is) and still scrolls past it once content overflows; this does not reintroduce ticket 61's "window grows past the screen" bug, since that came from an unbounded plain `Gtk.Box` driving the window's own natural-size request, not from a `ScrolledWindow` filling space it's already been allocated. The steps/items lists in column 2 originally kept ticket 69's "unchanged 240px-cap" treatment, but the user asked for the same fix there too once they saw column 1's result — same root cause, same fix: `steps_scroller`/`items_scroller` (`build_macro_editor_columns`/`build_stepper_editor_columns`) also swapped `propagate_natural_height`/`max_content_height(240)` for `set_vexpand(True)`.

**Second live-tested follow-up**: the user also flagged that column 3 (the editor controls, including the inline key/item picker) has no scroll fallback at all — a plain `Gtk.Box` appended straight into `build_library_content`'s `root`. `key_picker`'s own expandable "hi keycaps"/numpad toggle reveals can make it taller than the window, which would force the window to grow past the screen exactly like ticket 61's original bug (rather than "shorter than it needs to be," this is the opposite failure mode, unbounded growth). Fixed with a new `_scrollable_column3(col3)` helper — wraps column 3 in a `Gtk.ScrolledWindow` (`hscrollbar_policy=NEVER`, `vexpand=True`, default `vscrollbar_policy=AUTOMATIC`) — called from both the Macro and Stepper branches of `build_library_content` in place of the old bare `root.append(col3)`. Column 3's own `set_hexpand(True)` moved onto the wrapping scroller instead of the inner Box. Full suite re-verified green (258/258) after both changes.

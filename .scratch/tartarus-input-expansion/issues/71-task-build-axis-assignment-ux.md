## Question

Build axis assignment for real, against [Design Controller/Joystick axis output](./59-decide-controller-axis-output.md)'s settled Daemon model and [Prototype the axis-assignment GUI](./60-prototype-axis-assignment-ux.md)'s settled shape (variant B's fork/grid treatment, variant A's diagram picker, refined over five rounds of live reaction). No open design questions remain — this is implementation + live verification, per this map's "resolving a ticket means actually building and testing against the real, connected Tartarus Pro" discipline.

Scope, per ticket 59's Answer:

- **`Profile.axis_base` / `Profile.axis_held: HashMap<Input, AxisTarget>`** — a new parallel per-Layer map alongside the existing `bindings_*`/`chords_*` maps, not a new `Action` variant. `AxisTarget` is one of the 17 settled targets (5 unsigned: `ABS_Z`/`ABS_RZ`/`ABS_THROTTLE`/`ABS_GAS`/`ABS_BRAKE`; 6 signed axes × independently-assignable +/- halves: `ABS_X`/`Y`/`RX`/`RY`/`RUDDER`/`WHEEL`).
- **Mutual exclusion**: an Input present in a Layer's axis map is structurally excluded from that Layer's `bindings_*` map *and* from Chord membership on that Layer — `SetAxisAssignment` must clear any existing Binding/Chord-membership on the same (Layer, Input) atomically (mirrors `SetBinding`'s existing atomic-persist precedent), and `SetBinding`/`SetChordBinding` must reject a grid key that already has an axis assignment on that Layer with a specific error, not a silent overwrite.
- **Two new D-Bus methods**: `SetAxisAssignment(input, layer, target)` / `ClearAxisAssignment(input, layer)`, active-Profile-scoped and atomically persisted like `SetBinding`. `GetConfig()` gains the `axis_base`/`axis_held` maps.
- **`uinput` capability**: the existing single gamepad-identity `uinput` device (`injector.rs::build_gamepad_device`, from ticket 43) gains the 17 targets' underlying `ABS_*` codes (`ABS_Z`/`RZ`/`THROTTLE`/`GAS`/`BRAKE`/`X`/`Y`/`RX`/`RY`/`RUDDER`/`WHEEL` — 11 codes, the +/- halves share one `ABS_*` code each per ticket 59 §3) — no second device.
- **Live-depth-driven axis resolution**: reuses the key's existing Actuation/Release-point thresholds (tickets 17/19/26) as the axis's start/end thresholds — 0 output below Release, linear ramp to raw Depth above Actuation, per ticket 59 §4. Implement as its own seam, `(Depth, edge_event) → axis_value` (ticket 59 §7's forward-looking note), even though "Live/linear" is the only resolver built now.
- **Runtime conflict resolution** (ticket 59 §5): opposite halves of one signed axis — whichever key is already actively outputting suppresses the other. Same-half sharing — take the greater of the two Depths when both are pressed.
- **Digital Capture mode fallback** (ticket 59 §6): press/release step-increment; exact step size a build-time-tuned constant, same precedent as Analog-repeat's four TBD constants.
- **CONTEXT.md**: confirm the Axis assignment glossary entry (added in ticket 59) doesn't need a build-specific addendum.

Scope, per ticket 60's Answer:

## Answer

Built for real, on `main`, against ticket 59's Daemon model and ticket 60's settled GUI shape.

**Daemon (Rust)**:
- `config.rs`: `AxisTarget` (17-variant enum, closed, `#[serde(rename_all = "snake_case")]`), `AxisPolarity`, `Profile.axis_base`/`axis_held: HashMap<Input, AxisTarget>` (+ `axis_layer`/`axis_layer_mut` accessors mirroring `layer`/`chords`), and `resolve_axis_value(depth, point) -> u8` — the pure Live/linear resolver (0 below Release, linear ramp to raw Depth at Actuation, raw Depth above). `parse()` gained three new hand-edited-`config.toml` rejections: `InvalidAxisInput` (non-Grid), `AxisBindingConflict`, `AxisChordConflict` (same Input/Layer).
- `injector.rs`: `build_gamepad_device` now also declares the 11 `ABS_*` codes backing the 17 targets (unsigned `0..=255`, signed `-255..=255`) on the same single gamepad device (ticket 59 §3's "no second device" — evdev crate confirmed to support mixing `BTN_GAMEPAD` buttons with `ABS_*` axes freely). New `InjectorMessage::AxisValue`/`Injector::set_axis_value`, always routed to the gamepad sink, gated by suppression like every write but `ForceRelease`.
- `command.rs`/`dispatch.rs`: `Command::SetAxisAssignment`/`ClearAxisAssignment`. `SetAxisAssignment` atomically clears any existing Binding *and* any Chord membership for `(layer, input)` alongside the insert (mirrors `SetBinding`'s atomic-persist precedent); `SetBinding`/`SetChordBinding` reject a grid key already Axis-assigned there instead. Live-depth-driven resolution is its own seam per ticket 59 §7: a new `AxisState` (per-Input `contributions` + per-`ABS_*`-code `owners`) fed by two paths — the continuous Analog half reuses the existing `depth_tx`/`depth_rx` watch channel (ticket 26) via a new `rx_depth` parameter on `dispatch::run` and a `handle_depth_update` select arm; the Digital-mode fallback (`handle_axis_edge_event`) rides the ordinary Down/Repeat/Up stream, stepping by a build-time `AXIS_DIGITAL_STEP` constant, resetting to 0 on Up. Both funnel into `recompute_and_emit_axes`, which groups contributors by `ABS_*` code and applies ticket 59 §5's runtime conflict rules (`resolve_axis_contribution`, pure/unit-tested): same-half/same-target sharing takes the greater Depth; opposite signed halves let whichever key is already active keep winning, with an explicit (undocumented-by-ticket) tie-break toward positive on a genuinely simultaneous first activation. A Layer or Profile switch calls `reset_axis_outputs`, a true no-op when nothing has ever driven output (verified live against the existing test suite — an earlier unconditional-11-zero-writes version broke several unrelated exact-batch-count tests).
- `dbus/mod.rs` + `wire.rs`: `SetAxisAssignment`/`ClearAxisAssignment` methods mirroring `SetBinding`/`ClearBinding` exactly; `axis_target_to_str`/`axis_target_from_str` wire strings; `GetConfig()`'s `profile_to_dict` gained `axis_base`/`axis_held`.
- 41 new Rust tests (config/injector/dispatch/wire/dbus); 326/326 passing; `cargo clippy --all-targets` clean; `cargo fmt` applied.

**GUI (Python)**:

- New `axis_picker.py`: the diagram picker per ticket 60's five-round-refined shape — Left/Right Stick as 4-arm crosses with the stick's name above, Left/Right Trigger beside their respective stick, a rule below, then Driving (Wheel ±/Gas/Brake) and Flight (Rudder ±/Throttle) inline rows. Every signed half is its own button. `claimed_by` param drives the one-shot `.toast`-styled cross-key notice.

The Action dropdown itself is grid-only-gated (`is_grid_input`); `build_chord_binding_dialog`'s `chord_action_types` now also excludes `"axis"` (a Chord can no more drive a continuous axis than it can Profile Switch) — a gap ticket 71's own text didn't call out explicitly.

Chord-selection's `chord_click_override` now detects an Axis-assigned click and sets an inline `chord_ui["axis_error"]` message instead of toggling selection or disabling the button.

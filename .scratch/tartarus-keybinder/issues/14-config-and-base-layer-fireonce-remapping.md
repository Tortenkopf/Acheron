# 14 — Config file + minimal domain model + Base-layer Fire-once Keypress remapping

**What to build:** The Daemon reads a TOML config file and applies real remaps for simple, single-press bindings — the first user-visible "I typed X and got Y" behavior. Scope is deliberately narrow: one Profile (`Default`), Base Layer only, `Action::Keypress` only, `TriggerMode::FireOnce` only. See `.scratch/tartarus-keybinder/spec.md` ("Domain model (Daemon, Rust)" and "Config lifecycle") for the full design — this ticket implements a subset of it, not the whole domain model.

**Blocked by:** 13

**Status:** resolved

- [x] `Input` composite enum (`ModeKey`, `Grid(row, col)`, `Thumbstick(Direction)`, `Wheel(WheelEvent)`) exists with a custom `Display`/`FromStr` serializing to the flat snake_case strings (`mode_key`, `grid_r1c1`, `thumbstick_up`, `wheel_scroll_up`, `wheel_middle`, …) matching ticket 01's table exactly.
- [x] `Binding`, `Action::Keypress { modifiers, key }`, and `TriggerMode::FireOnce` types exist (other `Action`/`TriggerMode` variants can exist as stubs but don't need to function yet).
- [x] Config is a single TOML file at `~/.config/acheron/config.toml` with a top-level `schema_version = 1`.
- [x] A Layer's Bindings are a sparse map keyed by `Input`; an absent entry means passthrough (unchanged from ticket 13's behavior).
- [x] If `config.toml` is missing, the Daemon creates `~/.config/acheron/` and the file itself on startup, writing it immediately (not lazily) — seed content: one Profile named `Default`, `schema_version = 1`, empty Base-layer Binding map, set active.
- [x] If `config.toml` fails to parse or has an unsupported `schema_version`, the Daemon refuses to start: exits non-zero with a clear parse error to the journal/stderr, and does not overwrite or back up the file.
- [x] On startup with a valid config, the dispatch task resolves each `PhysicalEvent`'s `Input` against the `Default` Profile's Base Layer: a configured Binding fires its `Keypress` action on `Down` only (ignoring `Repeat`/`Up`); an absent Binding passes through unchanged (ticket 13 behavior).
- [x] Live-hardware demo: hand-edit `config.toml` to bind one grid key to a different Keypress, restart the Daemon, press the physical key, and the remapped key (not the original) appears in a real text field.
- [x] Automated tests (via ticket 13's fake `CaptureSource`) cover: passthrough when unbound, remap when bound, seed-on-missing-file, and refuse-to-start-on-corrupt-file.

## Comments

Implemented on top of ticket 13's skeleton, entirely within `daemon/`.

- `src/config.rs` (new) — the config-facing domain model and `config.toml` lifecycle. `Config { schema_version, active_profile, profiles: HashMap<String, Profile> }`, `Profile { base: HashMap<Input, Binding> }` (flat — no `Layer` enum/Held layer yet, that's ticket 18's job per the map), `Binding { trigger: TriggerMode, action: Action }`, `TriggerMode { FireOnce, HoldToRepeat, Toggle }`, `Action { Keypress { modifiers: Modifiers, key: evdev::KeyCode }, Macro { steps: Vec<MacroStepDto> } }`, `Modifiers` (plain ctrl/shift/alt/super bools rather than pulling in `bitflags` for four fields), `MacroStepDto` (KeyDown/KeyUp/Delay, matching issue 06's shape exactly — schema-only stub, not executed until ticket 17). `load_or_seed()` seeds-and-writes-immediately on a missing file (issue 11) and refuses to start (no overwrite/backup) on a parse failure, a non-integer/wrong `schema_version`, or an `active_profile` that doesn't name a real profile — each reported as a distinct `ConfigError` variant with a specific message rather than one generic error.
- `src/input.rs` — added `Input`'s `Display`/`FromStr` (issue 01's flat snake_case strings) plus hand-written `Serialize`/`Deserialize` (via the `Display`/`FromStr` round trip) so `Input` works directly as a TOML/`HashMap` table key. `all_injectable_key_codes()` widened from a curated list of this device's own physical keys to the full standard `EV_KEY` range (`0..=0x2ff`), since a Keypress's remap target is now arbitrary (any key the user picks in config, not just this device's own keys) and the virtual uinput device has to declare support for whatever it might be asked to inject.
- `src/injector.rs` — the injector task's channel now carries an `InjectorMessage` enum (`Physical` for ticket 13's passthrough, `Keypress` for a compiled Fire-once firing) so both keep funneling through the one task/fd (issue 07). `fire_keypress` sends a press frame (modifiers down, then key down) followed by a release frame (key up, then modifiers up in reverse) — the "canned modifier-down/key-down/key-up/modifier-up sequence" issue 06 describes.
- `src/dispatch.rs` — resolves each `PhysicalEvent` against the passed-in Base-layer bindings map: a bound Input fires its compiled Action on `Down` only (Repeat/Up produce no output at all, not even the original passthrough key); an unbound Input passes through exactly as ticket 13 did. `TriggerMode` isn't branched on yet — every trigger mode fires like Fire-once for now, since Hold-to-repeat/Toggle's real semantics are ticket 17's job. `Action::Macro` logs to stderr and no-ops rather than firing (or silently vanishing) — not implemented until ticket 17.
- `Cargo.toml` — added `serde` (derive), `toml`, `dirs` (for `~/.config` resolution), and `evdev`'s `serde` feature (its `KeyCode` already round-trips through serde as its `KEY_*` constant name string, matching spec.md's TOML sample `key = "KEY_F1"` exactly — no custom key-code (de)serialization needed). `tempfile` added as a dev-dependency for config-lifecycle tests that write/read real files without touching the real `$HOME`.
- Tests: 11 new unit tests (27 total via `cargo test`), all via ticket 13's fake `CaptureSource`/`RecordingSink` plus `tempfile`-isolated config-file tests — no real device or `$HOME` touched by the suite. `cargo clippy --all-targets -- -D warnings` and `cargo fmt --check` both clean.
- Live-hardware demo done 2026-08-14: ran the release binary against the real, connected Tartarus Pro with no existing `config.toml` — confirmed it seeded `~/.config/acheron/config.toml` immediately (empty `Default` profile, `schema_version = 1`, active). Hand-edited the seed to bind `grid_r1c1` to `KEY_9`, restarted the Daemon, and the user confirmed pressing the physical top-left grid key (stock output `1`) now types `9` in a real text field. Config was reset back to the clean empty seed afterward.
- `/code-review` caught two real issues, both fixed: (1) a `schema_version` present but of the wrong TOML type (e.g. a string or float) was misreported as `MissingSchemaVersion` even though the field is visibly present — split into a new `ConfigError::InvalidSchemaVersion` variant with its own message, plus a regression test; (2) a Down event on an Input bound to `Action::Macro` was silently swallowed with no output and no diagnostic — `fire()` now logs a clear stderr message naming the Input and ticket 17 before no-op'ing, so a hand-edited Macro binding doesn't look like a dead key.

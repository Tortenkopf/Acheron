- [Tartarus dual-stage grid keys](tartarus-dual-stage-keys/map.md) — **spec ready** (wayfinder, all six tickets resolved 2026-09-04). Charted the way to a gated [`spec.md`](tartarus-dual-stage-keys/spec.md) for "Dual-stage keys": a grid key in analog Capture mode may carry a second **Actuation stage** (its own Actuation/Release pair + `Binding`) firing at a Depth strictly deeper than the primary stage, with a user-selectable **Staging mode** (Handoff / No-Return / Additive / Quick-Skip) governing the handoff. No kill-gate (all software). Tickets 01–06 resolved; [`spec.md`](tartarus-dual-stage-keys/spec.md) + [ADR-0007](../docs/adr/0007-dual-stage-depth-interpretation-in-dispatch.md) + the `Actuation stage` / `Staging mode` / `Handoff` / `No-Return` / `Additive` / `Quick-Skip` `CONTEXT.md` entries are written. **Implementation is a fresh effort** — this map is done and can be archived. Key decisions in the spec: capture source unchanged, all staged-depth interpretation in a new pure `daemon/src/stage.rs` + non-pure `stage::Engine` (third depth engine alongside `axis`/`analog_repeat`) holding a `trigger::Slots<StageKey>`; cap at 2 stages; deep stage requires a primary, cascade-deletes with it; disjoint stacked bands (`deep.release > primary.actuation`); deep Binding per-Layer, deep ActuationPoint + mode per-Input per-Profile; four Staging-mode event-sequence tables (mechanical replay, no fast-ramp short-circuiting); Analog-repeat banned on dual-stage keys; Chord member ⇒ no deep stage; deep stage inert in Digital mode; seven new `ConfigError` variants + four granular `Edit` variants; GUI binding editor is one flat panel with a Primary/Deep swap toggle so only one key/button picker is ever mounted at once (prototype: `prototype/04-dual-stage-binding-editor-layout/`); Layer/Profile switch and the Digital-mode flip force-release both stages (`Effect::StopAllStages`), cascade-delete force-releases immediately (`Effect::StopStage`), reconnect gets a new explicit disconnect hook; no new `GetState()` field. Analog-repeat's pre-existing lack of dropout handling, surfaced while resolving the reconnect question, is explicitly out of scope as a separate effort.
